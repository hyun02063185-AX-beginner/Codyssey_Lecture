## ① 헌법 §3 보강 — 약어 조문 분리 (양쪽 저장소)

종합보고 권고 수용. `docs/톤앤매너.md` §3(용어)의 약어 규정을 **두 조문으로 분리**:

> **③-1 경영·업무 지표 약어** (KPI·VOC·ROI·CTR 등) — 대상 독자(실무 재직자)가 일상적으로 쓰는 용어이므로 풀이하지 않는다. 단, 입문 과정(첫걸음판)에서는 첫 등장 시 한 줄 풀이한다.
> **③-2 관용 로마자 표기** (FAQ·A/B·PDF·URL 등) — 한국어에서 이미 일반 명사처럼 쓰이므로 풀이 대상이 아니다. 양 과정 공통.
> **③-3 기술 개념 용어** (RAG·MCP·LLM·에이전트 등) — 첫 등장 시 반드시 한 줄 풀이하며, **같은 개념은 판·강의를 막론하고 동일한 풀이 문구**를 쓴다.

- 첫걸음판에도 동일 구조로 반영(③-1의 입문 과정 단서 포함).
- 용어 풀이 통일 규정(보류 ①)은 **③-3에 흡수** — 별도 조항 신설하지 않음(종합보고 권고: 강한 개정 불필요).
- tone-keeper 정의문 반영, 양쪽 §7 이식 이력 기록.

## ② 잔여 정리

- **`deno.lock`** — `.gitignore`에 추가(netlify dev 자동 생성물). 이미 생성된 파일은 삭제하지 않고 무시 처리.
- **`docs/에이전트_운영.md` 현행화** — "하네스 미구축" 등 낡은 서술을 실제 상태로 갱신(테스트 수: AX 86 / 첫걸음 126, 하네스 3종 구성, 표준 파이프라인에 규범 동기화 검사 포함). 양쪽 저장소.
- **보류항목_AX.md 정리** — 4라운드 신규 2건(20강 사례 슬라이드 없음 / 19강 과제의 회의 의존) 포함해 상태 정돈. 각 항목에 **판단 시점**(리허설 후 / 수요 발생 시 / 종결) 명시.

## ③ release-manager 가동 — 두 저장소 마감

1. 마감 전: `npm test` 양쪽, qa-runner 회귀 1회
2. **boundary-keeper "규범 동기화 상태 검사" 실행** — 이번 마감분(①②)까지 포함해 양쪽 규범 일치 확인 (신설 모드의 정식 첫 마감 적용)
3. **계획 요약 보고 → 사용자 승인 대기** (필수 게이트)
4. 승인 후:
   - **AX_Lecture**: 태그 `v1.5-verified` (메시지 예: "AX 20강 소급 검증 완료 — 4라운드 감사·헌법 5차 개정·경험판 정비") → push 1회
   - **AI_First_Step**: 규범 동기화분 push 1회 (태그 없음)
5. 마감 보고서 `order/마감보고_AX검증_v1.5.md` 저장:
   - 소급 검증 총괄 요약(라운드별 발견·조치)
   - 헌법 개정 누적 이력
   - **리허설 대기 목록**(장수 미달 6개 강 · 경험판 과제 유무 · 04강 전제 · 19강 과제 의존 등)
   - 다음 마일스톤 후보
