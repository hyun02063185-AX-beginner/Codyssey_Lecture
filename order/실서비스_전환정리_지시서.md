# CC 작업 지시서 — 실서비스 전환 정리 (게이트 제거·진단실 병합·마일스톤)

> 위치: `Last_Lecture/order/실서비스_전환정리_지시서.md` · 경로는 프로젝트 루트 기준.
> 목적: 시연용 임시 장치를 걷어내고, 진단실을 정식 기능으로 병합해 실서비스 기반을 만든다.
> **작업 순서가 중요** — 아래 번호 순서대로.

---

## 1. 만료 게이트 제거 (가장 먼저 — 배포본이 잠기는 문제)

- `index.html`의 시연 만료 게이트(2026-07-22 하드코딩)를 **완전히 제거**한다.
  날짜 연장이 아니라 게이트 로직 자체 삭제(관련 스크립트·안내 화면 마크업 포함).
- 제거 후 로컬에서: 날짜와 무관하게 정상 진입되는지 확인.
- main에 커밋 (예: "실서비스 전환: 시연 만료 게이트 제거").

## 2. 진단실 브랜치 main 병합

```bash
git checkout main && git pull
git merge feature/practice-room
```

- 충돌 발생 시: **양쪽의 최신 의도를 보존**하는 방향으로 해소 — main의 콘텐츠 보강(268장·도식 19종·variant)과 브랜치의 진단실(검사 3종·인터랙티브·제안서)이 서로 다른 파일 위주라 충돌은 적을 것으로 예상. `js/data.js`가 충돌하면 main의 슬라이드 + 브랜치의 진단실 데이터 양쪽 모두 유지.
- 병합 후 전 동선 확인(아래 5의 검증 목록).
- 병합 커밋 후, **브랜치는 삭제하지 말고 보존** (`feature/practice-room` — 히스토리 참조용).

## 3. 시연용 장치 정책 — "유지하되 문서화"

다음 장치들은 실서비스에서도 강사 운영 도구로 유용하므로 **제거하지 않는다**:
- `?unlock=1` (진단실 전층 해금 — 강의 중 시연용)
- `#/reset` (전체 초기화 — 강의 시작 전 준비용)
- `?view=mobile|pc` (강제 뷰)
- `?variant=personal` (7·8강 경험판)

대신 **`docs/운영자_치트시트.md`** 를 새로 만들어 위 장치 전부(+ 접속 URL 형식, Lv·스킨 해금 규칙, 진단실 층 해금 조건)를 강사용으로 한 장에 정리한다. 코드 변경은 없음 — 문서화만.

## 4. 마일스톤 태그

```bash
git tag -a v-curriculum-15min -m "커리큘럼 완성: 20강 15분 규격(268장) + 도식 19종 + 진단실 병합"
git push origin main --tags
```

- v-demoday 태그는 그대로(이동·삭제 금지).

## 5. 배포 확인 (push 후 Netlify 자동 재배포)

push가 나가면 Netlify가 자동 재배포한다. 배포 완료 후 **공개 URL에서** (시크릿 창 권장):

- [ ] 만료 게이트 없이 정상 진입 (날짜 무관)
- [ ] 인트로 4테마 → 입장 → 사유의 방 → 20강 렌더 (표본: 각 상자 1강 + 7강)
- [ ] `?variant=personal` — 7·8강 경험판 + P 뱃지
- [ ] **진단실 입장** — 검사 3종·층 구조·제안서 동작 (병합 결과 확인)
- [ ] `?unlock=1` · `#/reset` 동작
- [ ] 스킨 5종 전환, 모바일(또는 375px) 정상
- [ ] 콘솔 0건

로컬에서도 동일 검증 후 push할 것 (배포에서 처음 발견하는 일이 없게).

## 가드레일

- 콘텐츠(`data.js` 슬라이드)·엔진 로직은 이번 작업에서 변경하지 않는다 (병합 해소에 필요한 최소 조정만).
- `slidesPersonal`·v-demoday 태그 무변경.
- Netlify 배포 횟수 고려: 커밋을 모아 **push는 최종 1회** (1·2·3·4를 로컬에서 완료 후).
