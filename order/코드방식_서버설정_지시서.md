# CC 작업 지시서 — 수강 코드 방식 개편 (반 코드+이름) + 서버 상시 무충돌 설정

> 위치: `AX_Lecture/order/코드방식_서버설정_지시서.md` · **양쪽 저장소 작업** (LMS 함수·발급은 본진, 입장 UI·서버 설정은 양쪽).
> 사용자 결정 2건 집행: ① 개인별 코드·QR 카드 → **반 코드 1개 + 수강생 이름 입력** ② 두 서버 동시 구동이 **기본값으로 충돌 없게**. 권장 모델: 높음.

---

## A. 수강 식별 방식 개편

### A-1. 입장 UI (양쪽 — 🎫 내 정보 레이어)

- 입력칸 2개로 변경: **수강 코드**(강사가 알려준 반 코드, 예: 7월AX반) + **이름**
- 안내 문구 갱신: "강사가 알려준 코드와 이름을 입력하면 학습 진행 상황이 강사에게 전달됩니다 (이름 외 정보는 수집하지 않습니다)"
- 정규화: 양쪽 트림·전각→반각(기존), 이름 내부 공백 제거(김 철수→김철수)
- 저장 식별자 = `{반코드}-{이름}` (기존 code 자리 그대로 — 시스템 구조 변경 최소화)
- HUD 뱃지·`#/reset` 동작은 기존 그대로(식별자만 합성값)
- `?join=반코드`: 코드칸 프리필 + **이름칸에 포커스** (기존 코드가 있으면 무시 — 동일)

### A-2. track 검증 (본진 함수, 공용)

- 식별자에서 반코드 부분을 분리해 codes 테이블과 대조: `codes.code + '-'` 로 시작하는지 (startsWith 매칭 — 이름에 하이픈이 들어갈 가능성은 낮으나, 매칭은 "등록된 반코드 중 접두 일치"로 구현해 안전하게)
- 미등록 반코드 → 204 조용히 무시(기존 정책 유지)
- 이름 길이 상한(코드 전체 20자 규칙과 조화 — 필요시 상한을 30자로 완화하고 근거 보고)

### A-3. 발급 도구 단순화 (#/admin)

- 인원수 입력 **제거** — 발급 = **반 코드 1개 등록** (과정 + 반 이름 → codes에 1행)
- 결과 화면: 반 코드 크게 표시 + `?join=` 링크 + **QR 1개**(강의 슬라이드/화면에 띄우는 용도 — 기존 QR 벤더 재사용, 카드 그리드 인쇄 화면은 "반 안내 1장" 인쇄로 단순화)
- CSV 다운로드 **제거**(이름이 시스템에 들어오므로 오프라인 명부 불필요 — 대시보드가 곧 명부)
- 발급된 반 목록 조회는 유지

### A-4. 대시보드·집계

- 변경 최소: 매트릭스 행이 자연스럽게 `반코드-이름`으로 표시됨(코드 문자열 그대로) — 확인만
- 반 필터(접두어) 정상 동작 확인
- **동명이인**: 시스템 처리 없음 — 운영매뉴얼에 안내("같은 반에 동명이인은 이름 뒤 숫자: 김철수2")

### A-5. 문서

- `docs/LMS_운영매뉴얼.md` 개정(양쪽): 새 절차 — 개설 전(반 코드 1개 발급) → 첫 시간(화면에 URL·QR·반 코드 띄우고 "코드와 이름을 입력하세요" 멘트 예시) → 동명이인 처리 → 이름만 수집한다는 고지 문구 포함
- 치트시트 갱신. **개인정보 방침 갱신**: "코드만 저장" → "코드+이름 저장(이름 외 수집 없음)" — 16강 원칙 관련 서술 정합화

## B. 서버 상시 무충돌 설정

### B-1. netlify.toml 포트 고정 (각 저장소)

`[dev]` 블록에 포트를 명시해 **옵션 없이도 항상 같은 자리**에 뜨게:

| | AX_Lecture | AI_First_Step |
|---|---|---|
| port (접속 주소) | 8000 | 8001 |
| staticServerPort (내부 정적) | 3999 | 3998 |
| (기타 내부 포트) | CC가 확인 | 겹치지 않게 분리 |

- `netlify dev`가 쓰는 **모든 내부 포트**(정적·함수 서버 등)를 실측으로 확인해, 두 저장소가 어떤 순서로 떠도 충돌 0이 되게 전부 분리·고정. netlify.toml이 지원하지 않는 항목이 있으면 대안(스크립트 등)과 함께 보고.
- 고정 후 실증: **두 서버를 순서 바꿔 두 번 동시 기동**(AX→첫걸음, 첫걸음→AX) 모두 정상.

### B-2. docs/서버_실행_가이드.md 신설 (양쪽)

CC와 사용자 공용 가이드:
- 표준 명령: 각 폴더에서 `npx netlify dev` (옵션 불필요 — toml이 처리)
- 접속 주소 표: AX `localhost:8000` / 첫걸음 `localhost:8001` / 대시보드는 `localhost:8000/#/admin` 하나만 사용
- 언제 netlify dev가 필요한가(LMS·admin) vs python으로 충분한가(콘텐츠만)
- 트러블슈팅: EADDRINUSE(이미 떠 있는 서버 확인법·종료법), 함수 로드 확인법(`Loaded function` 4종)
- **CC 운영 규칙 명시**: "사용자가 서버 실행을 요청하면 이 가이드의 표준 명령을 그대로 사용한다"
- `docs/에이전트_운영.md`에 참조 한 줄 + **지시서 순차 실행 규칙 추가**: "같은 저장소를 대상으로 하는 지시서는 동시 실행하지 않는다 — 완료 보고 후 다음 실행. 병렬은 저장소가 겹치지 않을 때만."
