# CC 작업 지시서 — LMS 운영 기초 (코드 발급 + 운영 매뉴얼)

> 위치: `AX_Lecture/order/LMS_운영기초_지시서.md` · **AX_Lecture에서 실행**(공용 LMS이므로 함수·대시보드는 본진, 첫걸음은 동기화 확인만).
> 원칙: **가장 기본만.** 관리 화면·이름 매핑·코드 비활성화·수강생 계정은 만들지 않는다(강의 활성화 후 별도). 권장 모델: 높음.

---

## 0. 사람이 먼저 할 일 (Supabase SQL — CC가 `docs/supabase_setup.sql`에 추가해 제공)

```sql
create table codes (
  code text primary key,          -- 예: A반-07
  course text not null,           -- ax / aifirst
  batch text not null,            -- 반 이름 (예: A반)
  created_at timestamptz default now()
);
alter table codes enable row level security;
```

## ① 코드 발급 도구 (#/admin 안, 최소 UI)

- 대시보드 요약 헤더 근처에 **[🎫 코드 발급]** 버튼 → 레이어:
  - 입력: 과정(ax/aifirst 선택) · 반 이름 · 인원수(1~99)
  - 실행 → 새 함수 `codes`(POST, `x-admin-key` 검증)가 `반이름-01`~`NN` 생성·codes 테이블 insert(중복 시 해당 반 기존 코드 반환 — 재발급 안전)
  - 결과 화면: 코드 목록 + **두 가지 내보내기**
    ① **CSV 다운로드** (code, join링크 — 강사가 이름 열을 직접 덧붙여 명부로 쓰는 용도. 이름은 시스템에 넣지 않는다 — 16강 원칙)
    ② **인쇄용 코드 카드** — 코드 + `?join=` 링크 QR을 카드 그리드로(브라우저 인쇄로 A4 → 잘라서 배부). QR은 외부 서비스 없이 생성(경량 라이브러리 인라인 또는 canvas 구현 — 의존성 최소 원칙 유지, 방식 보고)
- 발급된 반 목록 간단 조회(같은 레이어 안, 반 이름·인원·발급일 — 그 이상 관리 기능 없음).

## ② 코드 검증 — 등록된 코드만 유효

- `track` 함수: insert 전 codes 테이블 조회 → **미등록 코드는 204로 조용히 무시**(에러 아님 — 수강생 UX에 벽을 만들지 않되, 유령 데이터만 차단).
- 프론트 코드 입력은 **변경하지 않는다** — 등록 여부를 프론트에서 검사하지 않음(코드 목록 노출 방지). 단, 입력 시 자동 정규화만 추가: 앞뒤 공백 제거·전각→반각 — 오타 계열 중 자동 교정 가능한 것만.
- 기존 자유 코드 사용(개인 테스트 등)은 이제 수집되지 않게 됨 — 치트시트에 명시.
- stats/brief는 변경 불요(events 기반 그대로). `?class=` 필터가 batch와 자연 일치.

## ③ docs/LMS_운영매뉴얼.md 신설 (강사의 일주일)

기능 설명서가 아니라 **운영 절차서**로:
1. **강의 개설 전날** — 코드 발급 → 카드 인쇄(또는 CSV) → 이름 명부는 CSV에 오프라인 기록
2. **첫 강의 시간** — 배부 → 안내 멘트 예시("카드의 QR을 찍으면 코드가 입력된 채 열립니다. 코드를 입력하면 진행 상황이 저에게 전달됩니다") → 미입력자도 학습엔 지장 없음 안내
3. **주중** — 대시보드 보는 법(매트릭스·⚠ 이탈 신호 읽는 법)
4. **주말/세션 전** — 브리핑 생성 → 다음 세션 준비에 반영
5. **과정 종료 후** — 데이터 처리 방침(보관 또는 "events 정리" 요청)
6. 문제 해결 짧게: 코드 분실(카드 재출력) · 오입력(정규화 범위 밖이면 새 코드 안내)
- 양 저장소에 배치(공유 규범 — 사이트별 조정 허용 대상, 과정명만 다름).

## 가드레일

- 이름·연락처 등 개인정보를 시스템에 저장하지 않는다(코드만). 관리 기능 확장 금지(발급·조회까지만).
- 수강생 화면 변경은 입력 정규화뿐. 새 발견은 보고만.
