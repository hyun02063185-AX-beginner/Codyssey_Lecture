# CC 작업 지시서 — LMS 3단계: AI 주간 브리핑

> 위치: `Last_Lecture/order/LMS_3단계_브리핑_지시서.md` · 경로는 프로젝트 루트 기준.
> **브랜치 `feature/briefing`에서 작업** (main=v1.2 무변경). **권장 모델: 엑스트라** — 프롬프트 설계·데이터 가공이 품질을 좌우.
> UX 준수: `docs/UX_원칙.md`. 전제: `.env`에 `AI_API_KEY`(Gemini) 등록 완료.

---

## 목표

대시보드의 집계 데이터를 AI가 **강사의 언어로 해석**해주는 주간 브리핑을 만든다.

```
[#/admin에서 브리핑 생성 클릭] → [Function brief: 집계 → 프롬프트 → Gemini] → [브리핑 텍스트 표시·복사]
```

- **사람 확인 지점 원칙(17강)을 제품이 실천**: 브리핑은 화면 표시·복사까지만. 자동 발송·자동 조치 없음.
- 호출 주체는 강사뿐(ADMIN_KEY 뒤) — 비용·남용 리스크 최소.

---

## 1. Netlify Function `brief`

- `netlify/functions/brief.js`. POST, `x-admin-key` 검증(stats와 동일), 분당 5회 레이트리밋(브리핑은 잦을 이유가 없음).
- 흐름: ① stats와 동일한 집계 수행(공통 로직은 모듈로 추출해 stats·brief가 공유 — 중복 구현 금지) → ② 집계 JSON을 아래 프롬프트에 삽입 → ③ Gemini 호출 → ④ 텍스트 반환.
- `?class=` 필터 지원(반별 브리핑).
- **제공자 어댑터**: Gemini 호출부를 한 함수로 격리하고, 주석으로 Anthropic/OpenAI 교체 예시. 모델명은 상수로(현행 Gemini 무료 티어의 표준 모델을 CC가 확인해 지정).
- 파라미터: temperature 낮게(0.3 안팎 — 보고서형), max output ~1000 토큰.
- 실패 처리: AI 오류 시 502 + "브리핑 생성 실패 — 잠시 후 재시도" (집계 데이터 자체는 대시보드에 이미 있으므로 앱은 정상). 키 미설정 시 안내 메시지.

## 2. 프롬프트 설계 (한국어 — 아래를 기본으로, CC가 다듬되 구조 유지)

**시스템 지시:**
```
당신은 AX(AI 전환) 교육 과정의 강의 운영을 돕는 조교입니다.
아래 수강 데이터(JSON)를 근거로 강사를 위한 주간 브리핑을 작성하세요.

원칙:
- 데이터에 있는 사실만 말합니다. 데이터에 없는 것을 추측하거나 지어내지 마세요.
- 수강생 코드는 그대로 표기합니다 (예: A반-03).
- 수치를 근거로 들되, 해석은 간결하게. 전체 500자 이내.
- 커리큘럼 참조: 20강 구성은 상자1 왜(01~05: 태도·검증·프롬프트·질문),
  상자2 도구(06~10: 지형도·지식검색·에이전트·자동화·스택),
  상자3 적용(11~15: 문서·콘텐츠·데이터·소통·워크플로우),
  상자4 지속(16~20: 보호·확인지점·리스크·문화·로드맵).
- 진단 최약축 권장 강의: 이해→01·06강, 활용→04·05강, 검증→03강, 안전→16강.

출력 형식 (각 섹션 2~3문장, 해당 데이터 없으면 섹션 생략):
## 이번 주 요약
(활동 수강생 수, 진행 흐름, 눈에 띄는 변화)
## ⚠ 개입 필요
(7일+ 미활동·정체 수강생 코드와 권장 조치 — 없으면 "없음")
## 팀 진단 해석
(리터러시 최약축/네이티브 분포/암묵지·건강검진에서 다음 세션 권장 1가지)
## 콘텐츠 신호
(완료 인원이 급감하는 강의 구간이 있으면 지적 — 없으면 생략)
## 다음 주 한 가지
(강사가 할 가장 값어치 있는 행동 1가지)
```

**사용자 메시지:** `기준일: {오늘 날짜}\n수강 데이터:\n{집계 JSON}`

- 집계 JSON은 브리핑에 필요한 필드만 추려 슬림하게(코드별 완료수·lastSeen·Lv, 강의별 완료 인원, 진단 평균들). 원본 이벤트·불필요 필드 제외 — 토큰 절약 + 프롬프트 명료.

## 3. 대시보드 연결 (#/admin)

- 요약 헤더 옆 **[📋 주간 브리핑]** 버튼. 클릭 → 로딩 표시 → 결과를 레이어(UX 원칙 3조)로 표시.
- 레이어: 마크다운 간단 렌더(## 헤더·리스트 수준), [복사] 버튼(텍스트), [다시 생성], 닫기.
- 반 필터가 걸려 있으면 그 반 기준으로 생성(레이어 제목에 표기: "A반 주간 브리핑").
- 연타 방지(생성 중 비활성).

## 4. 검증 (feature/briefing, netlify dev)

데이터 준비: 코드 3개로 상이한 상태 구성(완료 수 다르게, 1명은 created_at 과거로 미활동 연출, 진단 1~2명) — 검증 후 **테이블 다시 0건으로 정리**(v1.2 인계 상태 유지).

- [ ] 브리핑 생성: 5개 섹션 구조 준수, **데이터에 있는 사실만** 포함(코드·수치가 실데이터와 일치하는지 대조), 500자 안팎.
- [ ] ⚠ 섹션에 미활동자 코드 정확히 등장 + 권장 조치가 상식적.
- [ ] 최약축 → 권장 강의 매핑이 프롬프트 규칙대로.
- [ ] 반 필터 브리핑: 해당 반 데이터만 반영.
- [ ] 데이터 0명 상태: "데이터 없음" 취지의 정상 응답(환각으로 가짜 수강생을 만들지 않는지 확인 — 중요).
- [ ] 키 미설정(.env에서 임시 제거) → 친절한 오류, 앱 정상. 복원 후 재확인.
- [ ] AI_API_KEY·ADMIN_KEY 프론트/네트워크 비노출, 레이트리밋 동작.
- [ ] 수강생 화면·대시보드 기존 기능 회귀 없음, 콘솔 0건.
- [ ] 치트시트에 브리핑 사용법(+비용 메모: 무료 티어 한도) 추가.
- [ ] feature/briefing 커밋+push (병합은 검토 후 별도).
