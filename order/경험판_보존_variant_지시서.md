# CC 작업 지시서 — 경험판 보존: ①태그 박제 + ②variant 구조

> 위치: `Last_Lecture/order/경험판_보존_variant_지시서.md` · 경로는 프로젝트 루트 기준.
> 목적: 7·8강의 개인 경험판을 안전하게 보존하고, 앞으로 main을 범용 사례판으로
> 발전시키되 URL 스위치로 경험판을 꺼내 쓸 수 있게 한다.

---

## 배경 (왜 이 구조인가)

- main은 **범용 상품**(일반 사례)으로 발전시킨다. 개인 경험담(한방자료·NanoClaw·과학문제은행 등)은 강사 본인이 강의할 때만 꺼내 쓰는 **시그니처판**.
- 보존 이중화: **태그 = 역사 보존**(무슨 일이 있어도 돌아갈 데모데이 완성본), **variant = 현역 운용**(최신 기능 위에서 스위치로 전환).

---

## ① 태그 박제 (가장 먼저, 1분)

```bash
git checkout main && git status     # 깨끗한 상태 확인(미커밋 변경 있으면 먼저 커밋)
git tag -a v-demoday -m "데모데이 완성본 (경험판 7·8강 포함) 스냅샷"
git push origin v-demoday           # 태그만 원격 푸시 (원격 사용 중이면)
git tag -l                          # v-demoday 확인
```

- 이 태그는 이후 **절대 이동·삭제하지 않는다.**
- 원격 푸시가 곤란한 환경이면 로컬 태그만이라도 생성하고 보고서에 명시.

## ② variant 구조 구현 (main에서)

### 데이터 구조 (js/data.js)

7·8강 lecture 객체에 두 번째 슬라이드 배열 추가:

```js
// 개념 — 실제 필드명·구조는 data.js 관례에 맞출 것
lecture07: {
  ...,
  slides:         [ /* 기본판(현재는 경험판 복사본, 추후 범용판으로 교체 예정) */ ],
  slidesPersonal: [ /* 경험판 = 현재 slides 그대로 이동·보존 */ ]
}
// lecture08 동일
```

**중요**: 이번 작업에서 `slides`(기본)와 `slidesPersonal`은 **동일 내용**으로 시작한다
(현재 경험판을 slidesPersonal로 복사·보존하고, 기본 slides는 일단 그대로 둠).
→ 사이트는 어느 모드에서든 지금과 100% 동일하게 동작해야 한다.
→ 범용판 콘텐츠는 다음 작업에서 기본 slides만 교체한다.

### 전환 로직

- URL 파라미터 `?variant=personal` → 슬라이드 로드 시 `slidesPersonal`이 있으면 그것을 사용.
- 파라미터 없음(기본) → `slides` 사용. `slidesPersonal`이 없는 강의(7·8 외 전부)는 파라미터와 무관하게 `slides`.
- variant 상태는 **세션 동안 유지**(해시 라우팅으로 화면 이동해도 풀리지 않게 — 예: 최초 로드 시 읽어 전역 플래그로 보관). localStorage 저장은 하지 않는다(링크로만 제어, 평소 배포 링크는 항상 범용).
- 화면 표시: personal 모드일 때만 HUD나 구석에 아주 작은 뱃지(예: "P") 하나 — 강사만 알아볼 수준으로 은은하게. 기본 모드에선 아무 표시 없음.

### 가드레일

- 슬라이드 엔진·room·스킨·게이미피케이션·진단실 로직 변경 금지. **데이터 구조 + 로드 분기 + 뱃지**만.
- 7·8강 외 강의 데이터 미변경.
- 이어보기/완료 판정은 variant와 무관하게 기존 키 그대로(같은 강의로 취급 — 슬라이드 수가 두 판이 다를 수 있음을 이어보기 인덱스 범위 체크로 방어).
