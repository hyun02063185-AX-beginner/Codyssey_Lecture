### (b) `.claude/agents/tone-keeper.md` 수정 — §4 동기화 절차 준수 여부

`tone-keeper.md`를 두 저장소 간 `diff`로 직접 대조한 결과, **두 곳에서 차이가 발견됨**:

**차이 1 — "배열이 정본" 판정 원칙** (`c9ad190`에서 추가):
```
본진: 강당 slides 실개수(**배열이 정본** — js/data.js의 실제 slides 배열 길이를 세어 판정하고,
      주석·문서에 적힌 장수 표기는 참고하지 않는다. 표기가 실제와 다르면 그 자체를 편차로 별도 보고)
첫걸음: 강당 slides 실개수  ← 이 원칙 없음
```
이 원칙은 "AX만의 취향"이 아니라 **판정 방법론 자체의 일반적 개선**이다(문서·주석 표기와 실제 배열이 어긋날 수 있다는 문제는 어느 사이트든 발생 가능). 실제로 이 개정의 계기가 된 버그(구 헌법 수치 15~17장이 실제 20강 중 19강 미달로 나온 사건, `order/AX1라운드_조치_지시서.md`)는 AX 전용 사실관계지만, "배열을 기준으로 판정한다"는 규칙 자체는 사이트에 종속적이지 않다. 그런데 이 변경이 첫걸음 저장소에는 반영되지 않았고, 커밋 메시지(`c9ad190`)에도 `docs/엔진_경계.md` §7에도 "첫걸음에 반영했다/보류한다"는 기록이 전혀 없다 — §4 절차("어느 쪽에서 먼저 개정했는지, 상대 저장소에 언제·어떻게 반영했는지 또는 보류 사유를 기록한다")를 따르지 않았다.

**차이 2 — "경험판(`slidesPersonal`)" 예외 조항** (`179557a`에서 추가):
```
본진: 경험판(slidesPersonal)은 §2 경험판 조항에 따라 1인칭 서술·도구 고유명사 등장이 예외로
      허용된다 — 단 ① 프레이밍 슬라이드 존재, ② 개념 용어 풀이 통일 확인 대상
첫걸음: 이 조항 없음 (대신 "페르소나 원칙" — slidesVariants 오버라이드 관련 별도 조항 보유, L36)
```
이건 확인 결과 **정당한 divergence**로 판단된다. 첫걸음은 `slidesVariants`(부분 오버라이드 방식)를, 본진은 `slidesPersonal`(강 전체 교체 방식)을 쓰는 비대칭 구조라는 게 `엔진_경계.md` §3에 이미 명문화돼 있고, 첫걸음 쪽 `tone-keeper.md`에도 이미 자기 메커니즘에 맞는 별도 조항("페르소나 원칙")이 있다 — 즉 "같은 자리에 서로 다른 메커니즘을 설명하는 조항이 각자 있다"는 기존 관례를 그대로 따른 것이라 §4 위반으로 보기 어렵다.

- **차이 1(배열이 정본 원칙)**: **백포트 후보** — 방향: 본진 → 첫걸음. 사이트 종속적이지 않은 판정 방법론 개선이며 아직 이식되지 않음. 심각도: 중간(기능 장애는 아니나, §4 절차상 "기록 없이 미동기화 상태로 방치"된 점이 문제). **수용 가능 여부**: 현재 상태로는 수용 불가 — 최소한 "이식 보류 사유" 기록이 필요.
