## 배경

입장 화면에 버튼이 계속 늘고 있다(강의실 입장·스킨·수강 코드·진단실…). 모바일 반복학습이 핵심 시나리오이므로 **첫 화면은 얇게, 부가 기능은 레이어로** 재구성하고, 앞으로 기능이 늘어도 두꺼워지지 않게 원칙을 문서로 박는다.

---

## ① 입장 화면 개편

### 목표 상태 — 화면에는 딱 둘

1. **[강의실 입장]** — 유일한 주인공 버튼 (기존 워프 흐름 그대로)
2. **⚙️ 설정** — 작은 아이콘 하나. 누르면 레이어가 열림

그 외 어떤 버튼·입력란도 첫 화면에 두지 않는다.

### 설정 레이어 (모바일 = 바텀시트, PC = 우측/중앙 패널)

레이어 안에 섹션으로 정리:
- **스킨** — 기존 스킨 선택기 이동(5종 스와치 그리드, 잠금 뱃지 포함)
- **수강 코드** — 기존 코드 입력 UI 이동(안내 문구·현재 코드 표시·제거 포함)
- **초기화** — `#/reset`과 동일 동작의 버튼(확인창 1번)
- 섹션 구조는 **추가 확장이 쉽게**(다음 기능의 지정석)

레이어 공통: 바깥 클릭/ESC/닫기 버튼으로 닫힘, 열려도 배경 인트로 애니메이션 유지, 스킨 5종에서 대비 양호, 스크롤 가능(모바일 낮은 화면 대응).

### 진단실 노출 규칙

- **Lv2 미만: 입장 화면에서 완전 미노출** (잠긴 버튼조차 없음 — 존재를 모르게).
- **Lv2 도달: 입장 화면에 진단실 입구가 나타남** — 첫 도달 시 1회 등장 연출(은은하게, 예: 페이드인+짧은 안내 토스트 "진단실이 열렸습니다"). 이후엔 조용히 표시.
- 이 경우도 화면 요소는 최대 3개(입장·진단실·⚙️)를 넘지 않는다.
- `?unlock=1`이면 Lv 무관 표시(기존 시연 스위치 유지).

### 강의용 입장 링크 `?join=`

- URL에 `?join=A반` → 로드 시 설정 레이어의 **수강 코드 섹션이 자동 오픈**, 입력란에 `A반-`이 미리 채워진 상태(수강생은 번호만 입력).
- 코드 저장 후 레이어 자동 닫힘 → 바로 [강의실 입장] 가능.
- 코드가 이미 저장돼 있으면 `?join=`은 무시(재입력 강요 없음).
- 치트시트에 사용법 추가(QR에 이 링크를 넣는 운영 방식).

### HUD

- 코드 뱃지(🎫)·Lv 뱃지 등 기존 HUD는 유지하되, 이번 개편으로 입장 화면과 중복 표시가 생기면 정리.

## ② docs/UX_원칙.md 신설 (상시 원칙 — 이후 모든 지시서가 참조)

아래 내용을 담아 작성(문구는 다듬어도 좋으나 원칙은 유지):

1. **모바일 우선** — 반복학습의 기본 환경은 수강생의 폰. 모든 신규 UI는 375px에서 먼저 확인.
2. **입장 화면 최소주의** — 주인공 버튼 1개(+해금된 진단실, ⚙️) 상한. **세 번째 상시 버튼은 없다.** 새 기능은 ⚙️ 레이어 또는 방(씬) 내부에 자리 잡는다.
3. **레이어 패턴** — 부가 기능은 페이지 아닌 레이어(바텀시트). 열기 1탭, 닫기 1탭.
4. **점진 노출** — 잠긴 기능은 잠긴 채 보여주기보다, 해금 시점에 등장시킨다(보상 연출).
5. **탈출구 보장** — 어느 화면에서든 뒤로가기/닫기 1회로 이전 상태.
6. **스킨 전수 확인** — 신규 UI는 5개 스킨에서 대비·가독 확인.
7. **콘텐츠 우선** — 이론 20강 접근은 절대 게이팅하지 않는다(보상·부가만 게이팅).
8. **신규 기능 배치 결정 순서**: 방 내부? → ⚙️ 레이어? → 그래도 안 되면 별도 씬. 입장 화면 추가는 최후이자 예외.

+ 말미에 **UI 변경 시 점검 체크리스트**(375px·5스킨·탈출구·입장화면 요소 수·콘솔 0)를 붙여, 이후 지시서 가드레일에서 "docs/UX_원칙.md 준수"로 참조 가능하게.

## ③ docs/URL전환_체크리스트.md 신설 (로컬 → 공개 URL 전환 시)

현재는 로컬 중심 운영. 나중에 배포 전환할 때 빠뜨리지 않도록 문서화:

1. **Netlify 크레딧 확인** (매월 리셋) → Deploys 탭에서 지연/실패 배포 정리
2. **feature/lms → main 병합** (검토 후) → push 1회
3. **Netlify 환경변수 등록**: `SUPABASE_URL` / `SUPABASE_SERVICE_KEY` (로컬 .env와 동일 값)
4. 배포 완료 후 **공개 URL에서 함수 동작 확인**: 코드 입장 → Supabase Table Editor에 session_start insert 확인
5. **CORS 확인**: track 함수의 허용 도메인에 실제 배포 도메인 포함 여부(코드에서 확인·필요시 수정)
6. 공개 URL 전 동선 검증(시크릿 창): 입장 화면 개편 상태·레이어·`?join=`·진단실 해금·스킨·모바일 실기기
7. **QR 재생성**: `?join=반이름` 포함 링크로
8. 레이트 리밋·이벤트 적재 정상 확인 후, 치트시트의 URL들을 배포 주소로 갱신
