# CC 작업 지시서 — LMS 2단계: 강사 대시보드

> 위치: `Last_Lecture/order/LMS_2단계_대시보드_지시서.md` · 경로는 프로젝트 루트 기준.
> **브랜치 `feature/dashboard`에서 작업.** main(v1.1) 무변경.
> **권장 모델: 엑스트라** — 집계 로직 + 차트 + 신규 화면 설계가 얽힌 작업.
> UX 준수: `docs/UX_원칙.md` (신규 화면도 8원칙·점검 체크리스트 적용. 단, 대시보드는 강사용 PC 화면이 1차 — 모바일은 "무너지지 않는" 수준이면 됨).

---

## 목표

1단계로 쌓이는 events 데이터를 강사가 **보는** 화면을 만든다.

```
강사: #/admin 진입 → 접속 키 입력 → [Function stats가 Supabase 집계] → 대시보드 렌더
```

- 범위: **조회 전용.** 데이터 수정·수강생 관리·AI 해석(3단계)은 제외.
- 수강생 화면·수집 로직은 건드리지 않는다.

---

## 0. 사람이 먼저 할 일

- 접속 키 결정 → 로컬 `.env`(와 나중에 Netlify env)에 `ADMIN_KEY=원하는문자열` 추가. (강사만 아는 값 — 예: 임의 12자+)

---

## 1. 접근 — `#/admin` + 키

- 해시 라우트 `#/admin`. **입장 화면·레이어 어디에도 진입 버튼을 두지 않는다**(URL 직접 진입만 — 수강생 화면 오염 방지, UX 원칙 2조).
- 진입 시 키 입력 화면 → 입력값을 이후 모든 stats 요청 헤더에 실어 보냄. 키는 **서버(Function)에서만 검증**(`ADMIN_KEY` 비교) — 프론트에 키 값 하드코딩 금지.
- 키 오류 시 401 + "키가 올바르지 않습니다". 세션 동안 유지(sessionStorage — localStorage 아님, 브라우저 닫으면 만료).
- 치트시트에 접속법·키 관리 항목 추가.

## 2. Netlify Function `stats` (조회 서버)

- `netlify/functions/stats.js`. GET, 헤더 `x-admin-key` 검증(불일치 401). track 함수와 동일한 CORS·기본 위생.
- Supabase REST로 events 조회 후 **서버에서 집계해 요약 JSON만 반환**(원본 이벤트 나열 반환 금지 — 응답 슬림하게).
- 쿼리 파라미터 `?class=A반`(코드 접두어 필터, 선택) 지원.
- 반환 구조(예시 — CC가 다듬되 이 정보량 유지):

```json
{
  "generatedAt": "...",
  "students": [                       // 코드별 요약
    { "code": "A반-01",
      "completedLectures": [1,2,3,7], // lecture_complete의 lectureId 유니크
      "level": 2,                     // 최근 이벤트의 level/run_complete 반영
      "lastSeen": "...",              // 최근 이벤트 시각
      "diagnosis": {                  // 최신 diagnosis_result만 (종류별)
        "literacy": {...}, "native": {...}, "tacit": {...}
      },
      "proposal": true }
  ],
  "aggregate": {
    "studentCount": 12,
    "lectureCompletion": { "1": 10, "2": 9, ... },   // 강의별 완료 인원
    "diagnosisAverages": {
      "literacy": { "이해": 3.2, "활용": 3.8, "검증": 2.4, "안전": 3.1 },
      "native": 54,                    // 평균 지수
      "tacit": 21                      // 평균 위험도
    },
    "checkupAverage": { "방향": 2.8, "데이터": 2.1, ... }  // 조직 건강검진 5축(수집되는 경우)
  }
}
```

- 성능: 1단계 규모(수십 명 × 수백 이벤트)는 전량 조회 후 메모리 집계로 충분. 단, Supabase 조회에 `order=created_at.desc&limit=5000` 상한을 두고, 초과 시 응답에 `truncated: true` 표시.

## 3. 대시보드 화면 (`#/admin` 인증 후)

**별도 씬**(수강생 씬과 스타일 충돌 없게, 스킨 변수는 재사용하되 밀도 높은 표 중심 레이아웃). 섹션 4개:

### 3-1. 요약 헤더
수강생 수 · 평균 완주율 · 오늘 활동 수강생 수 · [반 필터 드롭다운(코드 접두어 자동 추출)] · [새로고침].

### 3-2. 진행 매트릭스 (핵심)
- 행 = 수강생 코드, 열 = 1~20강. 셀 = 완료(●)/미완료(빈칸). 행 끝에 완료 수·Lv·마지막 활동.
- **이탈 신호**: 마지막 활동 7일↑ 행은 코드 옆 ⚠ 표시.
- 열 헤더에 강의별 완료 인원 미니 바 — **어느 강에서 멈추는지**가 한눈에(콘텐츠 개선 근거).
- 20열 가로 스크롤 허용(상자 4색으로 열 그룹 구분).

### 3-3. 진단 집계
- **리터러시 평균 4축 레이더** — 진단실의 레이더 컴포넌트 재사용. 팀에서 가장 낮은 축 텍스트 표시("팀 최약축: 검증 → 03강 복습 권장").
- 네이티브 평균 지수 게이지 + 분포(전통파/병행파/네이티브 인원).
- 암묵지 평균 위험도 + 판정 분포.
- 조직 건강검진 평균 5축 레이더(데이터 있으면).
- 응답 수가 0인 항목은 "아직 데이터 없음" 슬롯.

### 3-4. 수강생 상세 (행 클릭)
- 매트릭스 행 클릭 → 레이어(UX 원칙 3조)로 개인 요약: 완료 목록·Lv·최근 활동·진단 3종 결과(있는 것만).

## 4. 검증 (로컬, feature/dashboard)

데이터 준비: 서로 다른 코드 3개(예: A반-01·02, B반-01)로 이벤트를 실제 발생시켜 둘 것(강의 완료 각각 다르게, 진단 1~2명).

- [ ] `#/admin` 키 없이 데이터 접근 불가(401), 올바른 키로 진입, 세션 유지·브라우저 재시작 시 재입력.
- [ ] stats 응답에 원본 이벤트 나열 없음, 프론트/네트워크에 Supabase 키·ADMIN_KEY 값 노출 없음(키는 요청 헤더의 사용자 입력값만).
- [ ] 매트릭스: 3명 × 완료 상태 정확(Supabase Table Editor와 대조), 강의별 미니 바, ⚠ 이탈 표시(테스트용으로 created_at 과거 데이터 1건 수동 insert해 확인).
- [ ] 반 필터: `A반` 선택 시 2명만.
- [ ] 진단 레이더가 실제 평균값과 일치(수기 계산 대조 1회).
- [ ] 행 클릭 상세 레이어 열림/닫힘 1탭.
- [ ] 수강생 화면 회귀 없음(입장·레이어·수집·`?variant=personal`·진단실), 콘솔 0건.
- [ ] 치트시트에 #/admin 사용법 추가.
- [ ] feature/dashboard 커밋 (push 가능, 병합은 검토 후 별도).
