# 개발 에이전트 운영 가이드

> `AI_First_Step/order/에이전트체계_구축_지시서.md` 산출물, 본진 복사판. `.claude/agents/`의
> 서브에이전트 5종을 언제·어떻게 부르는지 정리한 문서. **이 문서 자체는 사람이 읽는 운영 매뉴얼이지,
> 에이전트가 참조하는 헌법은 아니다**(헌법은 `docs/톤앤매너.md`·`docs/엔진_경계.md`).

---

## 원칙

1. **에이전트는 보고만 한다.** persona-reviewer·tone-keeper·qa-runner·boundary-keeper는 파일을 고칠
   도구 자체를 갖고 있지 않다(Edit·Write 미부여). 발견 사항을 읽고 무엇을 고칠지는 항상 사람이 결정한다.
2. **release-manager만 예외적으로 실행 권한이 있다.** 그래도 병합·태그·push 같은 되돌리기 어려운
   행동 직전에는 반드시 계획을 요약 보고하고 사용자 승인을 확인한 뒤에만 실행 단계로 넘어간다
   (17강 "사람 확인 지점 설계" 원칙 그대로).
3. **보고서는 `order/`에 저장한다.** 파일명 관례: `order/검증리포트_<범위>_<에이전트>.md`.
4. **판단이 애매하면 애매하다고 말한다.** 5종 모두 공통.

## 역할표

| 에이전트 | 역할 한 줄 | 주 호출 시점 | 실행 권한 |
|---|---|---|---|
| `persona-reviewer` | 수강자 관점(현재 실무자 단일 화자)으로 콘텐츠 검증 | 상자 콘텐츠 완성 직후 | 없음(보고만) |
| `tone-keeper` | 톤앤매너·규격 일관성 감사 | 콘텐츠 완성 직후 / 주기 감사 | 없음(보고만) |
| `qa-runner` | 기능 회귀 검증 일괄 실행 | 모든 구현 작업 후 | 없음(보고만) |
| `boundary-keeper` | 엔진/콘텐츠 경계·백포트 감시 | diff 발생 시 / 병합 전 | 없음(보고만) |
| `release-manager` | 병합·태그·인계 절차 집행 | 마일스톤 마감 시 | **있음**(승인 게이트 필수) |

## 호출 예시

- "상자1을 persona-reviewer로 검증해줘"
- "상자2를 tone-keeper로 감사해줘"
- "qa-runner 돌려줘"
- "이번 커밋 boundary-keeper로 확인해줘"
- "이번 마일스톤 release-manager로 마감해줘" → 계획 보고까지만 나오고 멈춘다. 계획을 확인한 뒤
  "승인, 진행해줘" 같은 명확한 승인을 다시 보내야 실행 단계로 넘어간다.

## 표준 파이프라인

```
콘텐츠 완성
  → persona-reviewer + tone-keeper (병렬 가능)
  → (사람: 발견 사항 보고 검토, 수정 여부·범위 결정)
  → 수정
  → qa-runner (+ 하네스 등록 후: npm test 포함)
  → boundary-keeper
  → (사람: 승인)
  → release-manager 마감
```

## 첫걸음판과의 차이

- `persona-reviewer`: 첫걸음은 김주임/박선배/최사장 다중 페르소나를 검증하지만, 본진은 페르소나
  variant 시스템이 아직 이식되지 않아 **실무자 단일 관점**만 본다. 이식되면 갱신할 것 —
  `AI_First_Step/docs/페르소나_작성_가이드.md`의 §본진 이식 메모 참고.
- `qa-runner`: 첫걸음의 `?variant=<페르소나키>` 표본 항목 대신, 본진 고유의 `?variant=personal`
  (7·8강 경험판)과 진단실(`#/practice`) 항목을 본다.
- 나머지(`tone-keeper`·`boundary-keeper`·`release-manager`)는 두 저장소에서 동일 정의를 쓴다.

## 하네스와의 관계

- 이 저장소에는 아직 테스트 하네스(`npm test`)가 구축되지 않았다(`AI_First_Step/order/
  하네스_구축_지시서.md` §4 "본진 적용" 단계에서 이식 예정).
- 이식되면: **하네스 = 결정론적 검사**(강의 수, 필수 필드, 이미지 경로 실존 등), **에이전트 = 상황
  판단**(위화감·어투 등) 원칙으로 `qa-runner` 0단계에 `npm test`가 추가된다.
