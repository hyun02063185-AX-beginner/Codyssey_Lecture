# LMS 운영 매뉴얼 — 강사의 일주일 (AX 실무 입문)

> 기능 설명서가 아니라 **운영 절차서**다. "이 버튼이 뭘 하는지"보다 "언제 뭘 해야 하는지"에 집중한다.
> 화면 조작법 자체는 `docs/운영자_치트시트.md`를 참고. 이 문서는 `order/LMS_운영기초_지시서.md`·
> `order/코드방식_서버설정_지시서.md` 실행 결과 — 반 코드+이름 입력 체계가 갖춰진 뒤의 표준 운영
> 흐름을 담는다.
> 원칙: **이름 외** 개인정보(연락처 등)는 시스템 어디에도 두지 않는다. 시스템은 **반 코드 + 학생이
> 직접 입력한 이름**만 안다(개정: 코드방식_서버설정_지시서 A — 이전엔 코드만 저장했으나, 개인별
> 코드 발급·CSV 명부 관리 대신 학생이 이름을 직접 입력하는 방식으로 바뀌면서 대시보드 자체가
> 명부 역할을 겸하게 됐다).

---

## 1. 강의 개설 전날 — 반 코드 발급

1. `#/admin` 접속 → 접속 키 입력 → **[🎫 코드 발급]** 클릭.
2. 과정(`ax`)·반 코드(예: "7월AX반") 입력 → **발급**. 반마다 코드 **1개**만 발급한다(개인별 코드가
   아니다 — 학생 개개인은 이 반 코드에 자기 이름을 붙여 입장한다).
   - 이미 그 반을 발급한 적이 있으면(중복 클릭·재접속 등) 새로 만들지 않고 **기존 반 코드를 그대로**
     보여준다 — 몇 번을 눌러도 코드가 늘어나지 않는다.
   - **반 코드에 하이픈(-)은 피한다.** 시스템이 "반코드-이름"을 하이픈으로 구분하기 때문에, 반
     코드 자체에 하이픈이 들어가면 대시보드의 반 필터 표시가 어색해질 수 있다(기능은 정상 동작).
3. 결과 화면에 반 코드가 크게 뜨고 QR도 함께 나온다. **🖨️ 반 안내 인쇄**로 A4 한 장을 뽑아 강의실
   화면·입구에 붙여두거나, 강의 시작 슬라이드에 QR을 그대로 띄워도 된다.
4. **CSV·개인별 카드는 없다** — 이름이 시스템에 직접 들어오므로 대시보드가 곧 명부다(§3 참고).
   강사가 오프라인으로 이름 목록을 따로 관리할 필요가 없다.

## 2. 첫 강의 시간 — 반 코드 공유 + 안내

1. 반 안내(인쇄물 또는 화면 QR)를 공개 — 개인별로 나눠줄 것이 없다, 반 전체가 같은 코드를 쓴다.
2. 안내 멘트 예시:
   > "화면의 QR을 찍으면 코드가 입력된 채 열립니다. 본인 이름을 입력하면 학습 진행 상황이 저에게
   > 전달됩니다."
3. **미입력자도 학습엔 전혀 지장 없다**는 점을 함께 안내한다 — 코드+이름은 순전히 진행 상황
   공유용이고, 입력하지 않아도 강의 진행·완주·게이미피케이션 전부 정상 동작한다. 부담 없이
   선택하게 한다.
4. **동명이인 안내**: 같은 반에 이름이 같은 학생이 있으면 뒤에 숫자를 붙여 구분하게 한다
   (예: "김철수" → "김철수2"). 시스템은 동명이인을 자동으로 구분하지 않는다 — 안내 멘트에 미리
   포함해두면 나중에 헷갈릴 일이 없다.
5. 입력한 반 코드가 **등록된 코드가 아니면**(오타·즉석 임의 코드 등) 학습 화면엔 아무 문제가 없지만,
   대시보드에는 잡히지 않는다 — 조용히 무시되는 구조이며 수강생에게 에러가 노출되지 않는다.

## 3. 주중 — 대시보드 보는 법

- `#/admin` → **진행 매트릭스**: 반 필터로 좁혀서 본다. 행은 `반코드-이름`(예: "7월AX반-김철수")
  형태로 표시된다 — **이 화면 자체가 명부**다. **⚠** 표시는 7일 이상 미접속 — 이탈 신호로 가장
  먼저 확인할 항목.
- **진단 집계**: 리터러시 4축 중 팀 최약축이 뜨면, 표시된 복습 강의를 다음 시간 도입부에 짧게 언급.
- 이 단계에서 **개별 개입**(연락 등)이 필요하면, 매트릭스 행의 이름으로 바로 누군지 알 수 있다
  (별도 명부 대조가 필요 없다 — 이전 방식과의 가장 큰 차이).

## 4. 주말 / 다음 세션 준비 전 — 브리핑

1. `#/admin` → **📋 주간 브리핑** 클릭(반/과정 필터 적용된 상태로 생성됨).
2. Gemini가 매트릭스·진단 집계를 바탕으로 요약 5개 섹션(이번 주 요약·개입 필요·팀 진단 해석·
   콘텐츠 신호·다음 주 한 가지)을 생성한다. **참고 자료**로만 쓴다 — 최종 판단은 매트릭스·진단
   집계 원본을 직접 보고 내린다.
3. "다음 주 한 가지" 섹션을 다음 세션 준비(도입부 멘트·복습 포인트)에 반영.

## 5. 과정 종료 후 — 데이터 처리

- 기본은 **보관**(다음 기수 비교, 콘텐츠 개선 근거로 재사용 가능). 이름이 포함돼 있으므로 보관
  기간에 대한 내부 방침이 있다면 그에 따른다.
- 완전 삭제를 원하면 개발자에게 "이 반(또는 이 과정) `events`·`codes` 정리" 요청 — SQL로 해당
  `course`/`batch` 행만 지운다(예시는 §6 참고). 삭제는 되돌릴 수 없으므로 반드시 명시적으로 요청.

## 6. 문제 해결

- **반 코드를 잊었다**(강사가 화면·인쇄물을 못 찾을 때): `#/admin` → 코드 발급 레이어의 "발급된
  반 목록"에서 반 코드 재확인. 같은 반 코드로 다시 발급을 눌러도 안전하다(재발급 안전, 새 코드가
  생기지 않는다).
- **오입력**(코드+이름이 대시보드에 안 잡힘): 입력창은 앞뒤 공백·전각 문자(가끔 모바일 자판에서
  전각으로 입력됨)를 자동 교정하고, 이름의 내부 공백은 자동 제거된다("김 철수"→"김철수"). 그래도
  안 잡히면 반 코드 자체가 틀렸을 가능성이 높다 — 화면·인쇄물의 정확한 반 코드를 다시 확인해준다.
  시스템이 등록 여부를 알려주진 않으므로(코드 목록 노출 방지), 강사가 대시보드에서 직접 확인하는
  것이 유일한 방법이다.
- **반을 잘못 발급했다**(오타 등): 이 도구는 발급만 하고 비활성화 기능은 없다(가장 기본만 — 이후
  필요해지면 별도 지시로 확장). 오발급된 반은 그냥 안 쓰면 된다 — 학생에게 코드를 알려주지 않으면
  대시보드에 아무 영향도 없다.
- **동명이인이 매트릭스에서 구분이 안 된다**: 시스템은 처리하지 않는다 — §2의 안내 멘트대로 학생이
  스스로 숫자를 붙이게 하는 것이 유일한 예방책이다. 이미 겹친 경우, 완료 강의 패턴(어느 강까지
  봤는지)으로 강사가 정황상 구분해야 할 수 있다.

## 부록 — 검증/정리용 SQL 예시

```sql
-- 특정 반의 코드·이벤트를 완전히 지울 때(되돌릴 수 없음 — 신중히)
delete from events where course = 'ax' and code like '7월AX반-%';
delete from codes  where course = 'ax' and batch = '7월AX반';
```
