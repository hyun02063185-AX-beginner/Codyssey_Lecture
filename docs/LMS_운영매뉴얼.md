# LMS 운영 매뉴얼 — 강사의 일주일 (AX 실무 입문)

> 기능 설명서가 아니라 **운영 절차서**다. "이 버튼이 뭘 하는지"보다 "언제 뭘 해야 하는지"에 집중한다.
> 화면 조작법 자체는 `docs/운영자_치트시트.md`를 참고. 이 문서는 `order/LMS_운영기초_지시서.md`
> 실행 결과 — 코드 발급·검증 체계가 갖춰진 뒤의 표준 운영 흐름을 담는다.
> 원칙: 이름·연락처 등 개인정보는 시스템 어디에도 두지 않는다. 시스템은 **코드**만 안다.

---

## 1. 강의 개설 전날 — 코드 발급

1. `#/admin` 접속 → 접속 키 입력 → **[🎫 코드 발급]** 클릭.
2. 과정(`ax`)·반 이름(예: "A반")·인원수 입력 → **발급**.
   - 이미 그 반을 발급한 적이 있으면(중복 클릭·재접속 등) 새로 만들지 않고 **기존 코드를 그대로**
     보여준다 — 몇 번을 눌러도 코드가 늘어나지 않는다.
3. 결과 화면에서 둘 중 편한 방식으로 준비:
   - **CSV 다운로드** — 코드·입장링크가 담긴 표. 여기에 강사가 **이름 열을 직접 덧붙여** 오프라인
     명부로 쓴다(이 이름은 시스템에 절대 올라가지 않는다 — 강사 PC/서류에만 존재).
   - **🖨️ 카드 인쇄** — 코드 + QR(스캔하면 입장 화면의 코드 입력창이 반 이름까지 채워진 채 열린다)이
     찍힌 카드 그리드를 A4로 인쇄 → 잘라서 1인 1장씩 배부할 수 있게 준비.
4. 이름 명부(CSV)는 강사가 **오프라인으로만** 관리한다 — 어떤 코드가 누구인지 기억하는 건 이 파일뿐,
   시스템은 모른다.

## 2. 첫 강의 시간 — 배부 + 안내

1. 카드(또는 구두로 코드)를 1인 1장씩 배부.
2. 안내 멘트 예시:
   > "카드의 QR을 찍으면 코드가 입력된 채 열립니다. 코드를 입력하면 진행 상황이 저에게 전달됩니다."
3. **미입력자도 학습엔 전혀 지장 없다**는 점을 함께 안내한다 — 코드는 순전히 진행 상황 공유용이고,
   입력하지 않아도 강의 진행·완주·게이미피케이션 전부 정상 동작한다. 부담 없이 선택하게 한다.
4. 입력한 코드가 **등록된 코드가 아니면**(오타·즉석 임의 코드 등) 학습 화면엔 아무 문제가 없지만,
   대시보드에는 잡히지 않는다 — 조용히 무시되는 구조이며 수강생에게 에러가 노출되지 않는다.

## 3. 주중 — 대시보드 보는 법

- `#/admin` → **진행 매트릭스**: 반 필터로 좁혀서 본다. **⚠** 표시는 7일 이상 미접속 — 이탈 신호로
  가장 먼저 확인할 항목.
- **진단 집계**: 리터러시 4축 중 팀 최약축이 뜨면, 표시된 복습 강의를 다음 시간 도입부에 짧게 언급.
- 이 단계에서 **개별 개입**(연락 등)이 필요하면, 코드로만 식별되므로 강사가 자기 명부(CSV)에서
  코드를 대조해 누군지 확인한다.

## 4. 주말 / 다음 세션 준비 전 — 브리핑

1. `#/admin` → **📋 주간 브리핑** 클릭(반/과정 필터 적용된 상태로 생성됨).
2. Gemini가 매트릭스·진단 집계를 바탕으로 요약 5개 섹션(이번 주 요약·개입 필요·팀 진단 해석·
   콘텐츠 신호·다음 주 한 가지)을 생성한다. **참고 자료**로만 쓴다 — 최종 판단은 매트릭스·진단
   집계 원본을 직접 보고 내린다.
3. "다음 주 한 가지" 섹션을 다음 세션 준비(도입부 멘트·복습 포인트)에 반영.

## 5. 과정 종료 후 — 데이터 처리

- 기본은 **보관**(다음 기수 비교, 콘텐츠 개선 근거로 재사용 가능).
- 완전 삭제를 원하면 개발자에게 "이 반(또는 이 과정) `events`·`codes` 정리" 요청 — SQL로 해당
  `course`/`batch` 행만 지운다(예시는 §6 참고). 삭제는 되돌릴 수 없으므로 반드시 명시적으로 요청.

## 6. 문제 해결

- **코드 분실**(카드를 잃어버렸다는 학생): `#/admin` → 코드 발급 레이어에서 CSV 재다운로드 →
  본인 코드 확인해 알려주거나, 카드를 다시 인쇄해 재배부.
- **오입력**(코드가 대시보드에 안 잡힘): 입력창은 앞뒤 공백·전각 문자(가끔 모바일 자판에서 전각으로
  입력됨)는 자동 교정한다. 그래도 안 잡히면 애초에 등록된 코드가 아닐 가능성이 높다 — 명부(CSV)에서
  정확한 코드를 다시 확인해 알려준다. 시스템이 등록 여부를 알려주진 않으므로(코드 목록 노출 방지),
  강사의 명부 대조가 유일한 확인 경로다.
- **반을 잘못 발급했다**(오타 등): 이 도구는 발급만 하고 비활성화 기능은 없다(가장 기본만 — 이후
  필요해지면 별도 지시로 확장). 오발급된 반은 그냥 안 쓰면 된다 — 학생에게 코드를 나눠주지 않으면
  대시보드에 아무 영향도 없다.

## 부록 — 검증/정리용 SQL 예시

```sql
-- 특정 반의 코드·이벤트를 완전히 지울 때(되돌릴 수 없음 — 신중히)
delete from events where course = 'ax' and code like 'A반-%';
delete from codes  where course = 'ax' and batch = 'A반';
```
