# 엔진 경계 — 복제·이식의 지도

> 이 저장소를 복제해 새 사이트("AI 첫걸음" 등)를 만들기 전에 읽는 문서.
> "무엇을 그대로 가져가고, 무엇을 새로 채우는가"를 정의한다. `js/공용화_지시서.md`(order/) 산출물.

---

## 1. 공유 엔진 (양 사이트 동일 유지 — 함부로 갈라치지 않는다)

| 파일/영역 | 역할 |
|---|---|
| `js/slides.js` | 슬라이드 렌더·네비게이션·확대(zoom) 엔진 |
| `js/room.js` | 상자 4개·카드 부채꼴 전개 |
| `js/main.js` | 씬 매니저·해시 라우터·진행도/Lv/스킨 상태·유틸 레이어(🎫/🎨) 시스템 |
| `js/telemetry.js` | 수강 코드 + 이벤트 수집(fail-silent) |
| `js/admin.js` | 강사 대시보드(`#/admin`) 오버레이 |
| `netlify/functions/*` | track·stats·brief·`_shared/aggregate.js` 전체 |
| `css/style.css`의 **스켈레톤**(레이아웃·컴포넌트 셀렉터) | 스킨 값 블록을 소비하는 CSS 구조 자체 |

이 파일들을 고치는 이유가 "이 사이트만의 취향"이 아니라 "버그·구조 개선"이라면 **두 사이트 모두에 반영**하는 게 원칙(§4 이식 절차).

## 2. 사이트 고유 (복제 후 각자 채운다)

| 파일/영역 | 역할 |
|---|---|
| `js/site-config.js` | 이 사이트를 정의하는 단일 설정(course·이름·문구·스킨 기본값·fxLevel·practiceRoom 등) |
| `js/data.js` | 커리큘럼 콘텐츠(상자·강의·슬라이드) — 전량 교체 대상 |
| `assets/*.svg`, `assets/*` | 강의 도식·이미지 |
| `css/style.css`의 **스킨 값 블록**(`:root[data-skin="..."]{ --bg:...; --ink:...; }`) | 색상·타이포 변수 값 자체(구조가 아니라 값) |
| `js/intro.js`의 인트로 테마 **구성**(`site-config.js`의 `introThemes` 배열이 어떤 테마를 쓸지) | 테마 렌더 알고리즘 자체는 §3 참고 — "몇 개, 어떤 걸 쓸지"만 사이트 선택 |

## 3. 경계 애매 항목과 판단 기준

완전히 한쪽으로 나뉘지 않는 것들 — 복제 시점에 실제로 판단이 필요하다.

- **`js/practice.js`(진단실)**: 스테이션 내비게이션·시험 엔진·캔버스 레이더 같은 뼈대는 재사용 가치가 높지만,
  문항 내용(`LIT_Q`/`NAT_Q`/`TAC_Q`/`AXES`/`STATIONS`의 텍스트)은 AX 커리큘럼에 강하게 결합돼 있다.
  `SITE_CONFIG.practiceRoom=false`로 기능 자체를 끌 수는 있게 해뒀지만(진입 버튼·`#/practice` 라우트 모두 차단),
  **진단실을 켠 채로 새 사이트를 만든다면 이 파일은 사실상 "공유 뼈대 + 사이트 고유 문항"의 혼합 파일**이 된다 —
  복제 시 문항을 통째로 다시 쓸지, 뼈대만 추출해 별도 모듈로 뺄지는 그때 가서 판단.
- **`"사유의 방"` 스킨 이름**: `SITE_CONFIG.siteName`과 우연히 같은 문자열이지만, 스킨 카탈로그의 표시명
  (`skin-lb`)은 이번 리팩터에서 SITE_CONFIG로 옮기지 않고 그대로 두었다. 사이트명과 스킨명이 항상 같이
  가야 하는 건 아니므로, 복제 사이트가 이 스킨을 그대로 쓴다면 이름을 따로 정할지 결정 필요.
- **입장 화면 안내문("사유의 상자 하나를 열어보세요" 등)**: "상자" 메타포 자체는 `data.js`의
  `CURRICULUM.boxes` 구조(엔진 개념)와 맞닿아 있지만, 문장의 색깔("사유의")은 사이트 고유에 가깝다.
  이번 리팩터에서는 site-config로 옮기지 않았다(범위 조절) — 다음 정리 때 후보.
- **인트로 테마 렌더 로직(`js/intro.js`의 `THEMES` 객체 — 별똥별/벚꽃/불꽃놀이/함박눈 그리기 알고리즘)**:
  코드 자체는 공유 엔진이지만, `#intro-grid`의 4분할 버튼(`index.html`)은 아직 **정적 마크업**이라
  테마 개수를 바꾸려면(예: 3개로 축소, 5번째 테마 추가) `index.html`도 함께 고쳐야 한다 —
  `introThemes` 배열만으로는 완전히 끝나지 않는다.
- **Supabase 프로젝트를 공유할지 분리할지**: `course` 컬럼으로 한 프로젝트 안에서 여러 사이트를
  구분하도록 만들어뒀다(§5). 그러나 이는 기본값일 뿐 — 완전히 별도 계정/프로젝트로 분리하는 것도
  선택지다(장점: 사고 격리·독립 요금제. 단점: 강사 대시보드를 둘 다 봐야 하면 로그인을 두 번 해야 함).

## 4. 이식 절차 — "AI 사이트에서 고친 엔진 버그/개선을 본진(AX)에 반영"

새 사이트에서 §1(공유 엔진) 파일을 고쳤다면, 그 개선은 본진에도 반영한다(본진이 "엔진 원본" 지위를 유지).

1. AI 사이트 저장소에서 수정.
2. AI 사이트 로컬(`netlify dev`)에서 아래 **검증 최소 세트** 통과.
3. 같은 변경분을 본진(AX, 이 저장소) `feature/*` 브랜치에 수동 적용(파일이 갈라졌다면 `git diff`로 대조
   후 patch, 아직 안 갈라졌다면 `git cherry-pick`도 가능).
4. 본진에서도 **검증 최소 세트** 재통과 확인 후 커밋·병합.

**diff 대상 파일** (이 목록 밖의 파일이 걸려 있다면 "엔진 개선"이 아니라 "사이트 고유 변경"이 섞였을 가능성 —
멈추고 분리):
`js/slides.js` · `js/room.js` · `js/main.js` · `js/telemetry.js` · `js/admin.js` ·
`netlify/functions/track.js` · `netlify/functions/stats.js` · `netlify/functions/brief.js` ·
`netlify/functions/_shared/aggregate.js` · `css/style.css`(스킨 값 블록 제외 — 셀렉터/레이아웃만)

**검증 최소 세트** (docs/UX_원칙.md 체크리스트와 함께):
- [ ] 입장·강의 진행·진단실(켜져 있다면)·스킨 전환·이어보기·`?variant=` 표본 회귀 없음
- [ ] `#/admin` 진입·매트릭스·진단 집계·📋 주간 브리핑 정상
- [ ] 375px 레이아웃 안 깨짐, 콘솔 0건, 키 비노출

## 5. 복제 절차 — 새 사이트 만들기

1. 이 저장소를 복제(git clone 또는 템플릿으로 새 리포 생성).
2. **`js/site-config.js` 전체 값 교체** — `course`부터 `finalMessage`까지. `course`는 짧은 영소문자
   식별자로(예: `'aifirst'`) — Supabase `events.course` 값과 동일해야 한다.
3. **`js/data.js` 콘텐츠 전량 교체** — 새 커리큘럼(상자·강의·슬라이드).
4. **스킨**: `css/style.css`의 스킨 값 블록을 그대로 쓸지, 새 팔레트로 바꿀지 결정 후 교체.
   `SITE_CONFIG.availableSkins`/`defaultSkin`이 실제 정의된 스킨과 어긋나지 않는지 확인.
5. **`assets/`** 도식(SVG 등)을 새 콘텐츠에 맞게 교체.
6. **Supabase는 기본적으로 공용**(§3 참고) — 같은 프로젝트를 쓴다면 `.env`의
   `SUPABASE_URL`/`SUPABASE_SERVICE_KEY`는 두 사이트가 동일한 값을 쓰고, `SITE_CONFIG.course`만
   다르게 설정하면 `events` 테이블 하나에 두 과정 데이터가 `course`로 구분돼 쌓인다.
   `ADMIN_KEY`·`AI_API_KEY`는 사이트별로 새로 발급하는 것을 권장(강사 대시보드 접근을 분리하고 싶다면).
7. **Netlify**: 새 사이트용 Netlify 프로젝트를 새로 만들어 이 저장소(복제본)를 연결, 환경변수 4종
   (`SUPABASE_URL`·`SUPABASE_SERVICE_KEY`·`ADMIN_KEY`·`AI_API_KEY`) 등록. `docs/URL전환_체크리스트.md` 참고.
8. **검증**: §4의 검증 최소 세트 + docs/UX_원칙.md 체크리스트 전체 실행.
