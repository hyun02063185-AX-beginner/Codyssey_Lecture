## 원칙

1. **모바일 우선** — 반복학습의 기본 환경은 수강생의 폰이다. 모든 신규 UI는 **375px에서 먼저** 확인한다.

2. **입장 화면 최소주의** — 상시 버튼은 **주인공 1개(강의실 입장) + 해금된 진단실 + ⚙️** 상한.
   **세 번째 "상시" 버튼은 없다.** 새 기능은 ⚙️ 레이어 또는 방(씬) 내부에 자리 잡는다.

3. **레이어 패턴** — 부가 기능은 페이지가 아니라 레이어(모바일=바텀시트, PC=중앙/우측 패널)로 연다.
   열기 1탭, 닫기 1탭(바깥 클릭·ESC·닫기 버튼 모두 동작).

4. **점진 노출** — 잠긴 기능은 잠긴 채 보여주기보다, **해금 시점에 등장**시킨다(은은한 연출 1회 + 이후는 조용히 표시).
   존재를 미리 예고해 조바심을 주지 않는다.

5. **탈출구 보장** — 어느 화면·레이어에서든 뒤로가기/닫기 1회로 이전 상태로 돌아갈 수 있다.

6. **스킨 전수 확인** — 신규 UI는 5개 스킨(사유의 방·페이퍼·네온·픽셀·블루프린트) 모두에서 대비·가독을 확인한다.

7. **콘텐츠 우선** — 이론 20강 접근은 **절대 게이팅하지 않는다.** 게이팅 대상은 보상·부가 기능(스킨, 진단실)뿐이다.

8. **신규 기능 배치 결정 순서** — ① 방(씬) 내부에 넣을 수 있는가? → ② ⚙️ 레이어 섹션으로 넣을 수 있는가?
   → ③ 그래도 안 되면 별도 씬. **입장 화면에 상시 요소를 추가하는 것은 최후이자 예외**이며,
   추가한다면 이 문서를 함께 갱신한다.

## UI 변경 시 점검 체크리스트

새로운 화면·버튼·레이어를 추가하거나 바꿀 때 아래를 확인한다:

- [ ] **375px**(모바일 세로)에서 레이아웃·터치 타깃 정상
- [ ] **5개 스킨** 전수에서 대비·가독 확인
- [ ] **탈출구** — 뒤로가기/닫기 1회로 이전 상태 복귀 가능
- [ ] **입장 화면 요소 수** — 상시 버튼이 상한(주인공 1 + 진단실 + ⚙️)을 넘지 않는가
- [ ] **콘솔 0건**
