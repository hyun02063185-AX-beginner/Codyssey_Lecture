# 서버 실행 가이드 (AX_Lecture)

> CC와 사용자 공용. `order/코드방식_서버설정_지시서.md` B — 두 저장소를 어떤 순서로 띄워도
> 충돌 없게 포트를 고정한 뒤의 표준 절차. **CC 운영 규칙**: 사용자가 "서버 실행해줘" 등으로
> 요청하면 이 가이드의 표준 명령을 그대로 쓴다(임의로 다른 포트·옵션을 붙이지 않는다).

---

## 표준 명령

이 폴더에서:

```bash
npx netlify dev
```

옵션이 필요 없다 — `netlify.toml`의 `[dev]` 블록이 포트를 이미 고정해뒀다(아래 표).
`--port`·`--offline` 같은 플래그를 직접 붙이지 않는다(붙이면 toml 설정과 꼬일 수 있다).

## 접속 주소

| | AX_Lecture (이 저장소) | AI_First_Step |
|---|---|---|
| 사이트 | `http://localhost:8000` | `http://localhost:8001` |
| 강사 대시보드 | `http://localhost:8000/#/admin` | (별도 접속 불필요 — 아래 참고) |
| 내부 정적 서버 | 3999 (사용자가 직접 열 일 없음) | 3998 |

**대시보드는 `localhost:8000/#/admin` 하나만 쓰면 된다** — 두 사이트가 같은 Supabase
프로젝트를 `course` 컬럼(`ax`/`aifirst`)으로만 구분해 공유하므로, AX 쪽 대시보드에서
과정 필터로 첫걸음 데이터도 그대로 보인다. 첫걸음 사이트를 따로 띄운 건 학습 화면
확인용이지, 대시보드를 거기서도 열 필요는 없다.

## 언제 `netlify dev`가 필요한가 vs `python -m http.server`로 충분한가

- **`netlify dev` 필요**: 코드 발급(`#/admin` → 🎫)·강사 대시보드·주간 브리핑·수강 코드
  수집(telemetry) 등 **서버 함수(`netlify/functions/*`)나 Supabase가 관련된 작업**을
  확인할 때. 함수가 실제로 호출돼야 의미 있는 검증이 된다.
- **`python -m http.server`로 충분**: 슬라이드 콘텐츠·스킨·게이미피케이션(Lv·스킨 해금)처럼
  **localStorage만 쓰고 서버 함수를 안 부르는** 화면 확인. 뜨는 속도가 빠르고 `.env` 키가
  전혀 필요 없어 가볍다. `.claude/launch.json`의 `static` 설정 참고.

## 트러블슈팅

### `EADDRINUSE` (포트가 이미 사용 중)

가장 흔한 원인은 **이전에 띄운 `netlify dev`가 완전히 종료되지 않고 남아있는 경우**다.

1. 확인 (PowerShell):
   ```powershell
   Get-NetTCPConnection -LocalPort 8000,3999 -ErrorAction SilentlyContinue |
     Select-Object LocalPort,OwningProcess
   ```
2. 그 PID가 실제로 netlify 프로세스인지 확인(다른 무관한 프로세스를 죽이지 않기 위해):
   ```powershell
   (Get-CimInstance Win32_Process -Filter "ProcessId=<PID>").CommandLine
   ```
3. 종료:
   ```powershell
   Stop-Process -Id <PID> -Force
   ```
   **주의**: Bash `kill`은 `npx`가 감싸 실행한 node 프로세스를 못 죽이는 경우가 있었다
   (실측 확인 — bash job은 종료된 걸로 보이는데 실제 Windows 프로세스는 살아남아 포트를
   계속 점유). **포트 정리는 PowerShell `Stop-Process`를 쓴다.**
4. 그래도 안 풀리면 `netlify:8000`처럼 이름이 겹치는 다른 저장소 서버가 떠 있는 게 아닌지
   확인 — 이번 포트 고정(B-1) 이전엔 두 저장소가 기본값(8899 근처, 정적 서버 3999)을
   그대로 써서 자주 충돌했다. 지금은 저장소별로 분리돼 있으니, 여전히 충돌한다면 十중팔구
   설정 없이 뜬 낡은 프로세스다.

### 함수가 제대로 로드됐는지 확인

정상 부팅 로그에 아래 4줄이 **전부** 있어야 한다(순서는 매번 달라질 수 있음):

```
⬥ Loaded function track
⬥ Loaded function stats
⬥ Loaded function brief
⬥ Loaded function codes
```

하나라도 빠지면 `netlify/functions/` 안의 해당 파일에 문법 오류가 있을 가능성이 높다 —
`node --check netlify/functions/<파일>.js`로 먼저 확인.

### 그 외 내부 포트(신경 쓸 필요 없음)

`netlify dev`는 부팅 시 위 표에 없는 포트(인스펙터·내부 IPC 등)도 몇 개 더 연다 — 실측
결과 이 포트들은 **실행마다 OS가 무작위로 비어있는 걸 골라 쓴다**(고정값이 아니다).
그래서 두 저장소를 동시에 띄워도 이 포트들끼리 충돌할 일이 없고, `netlify.toml`에 고정할
수도 없다(설정 항목 자체가 없음). 신경 써야 할 고정 포트는 위 표의 두 개(`port`·
`staticServerPort`)뿐이다.
